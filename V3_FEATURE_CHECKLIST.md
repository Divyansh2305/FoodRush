# FoodRush V3 — Feature Checklist

## Security & account data
- Server-side account store in `data/users.json` with salted scrypt password hashes.
- Browser stores only the signed session token and safe user profile.
- Per-user cart, orders, addresses, restaurant favorites, grocery wishlist, tickets, preferences and coupon history.
- Protected account routes wait for auth restoration before redirecting.
- Card number, CVV and raw UPI data are never written to order history; only a masked payment label is retained.
- Password change, password reset, account verification, sign out and account deletion flows.
- Mobile one-time-code sign-in and verification flows.

## Cart, offers & checkout
- Food and grocery grouping, item notes, quantity limits and restaurant-change confirmation.
- Coupon eligibility by scope and rules: RUSH60, FREEDEL, QUICK50, QUICK100, WELCOME25.
- First-order and grocery-only coupon checks.
- Tip, delivery instructions, platform/handling/delivery/tax breakup and clear-cart confirmation.
- Saved address selection, labels, schedule choices and contactless delivery.
- UPI, card, wallet and COD presentation; COD order-value eligibility.
- Future-expiry and Luhn card validation, payment failure/retry state and safe masked payment metadata.

## Orders & tracking
- Persisted order timeline shared by order list, success page and tracking page.
- Working reorder, cancellation rules, help link, rider card/call action and receipt download.
- Delivery map-style progress view and rating/review flow.

## Restaurants & discovery
- Current-location and manual-location discovery through the local API proxy.
- Dynamic API host configuration; LAN-compatible backend binding.
- Cache, request throttling/rate limiting and Overpass/Nominatim fallbacks.
- Recent searches, autocomplete suggestions and offline last-results fallback.
- Veg, open-24/7, fast-delivery, budget and sorting filters.
- Cuisine-aware FoodRush menu templates and customer review presentation.

## FoodRush Quick
- Product imagery, brands, variants, stock state, quantity limits and accurate category counts.
- Product detail pages, similar/substitute products and grocery wishlist.
- Grocery coupon banners aligned with checkout rules.

## Account, support & company
- Profile, orders, addresses, favorites, tickets and security settings.
- Help search, FAQ flows, contact form, order selector, local chat, call and email actions.
- User ticket history/status management.
- Partner application with saved reference ID.
- About, Careers, Corporate, Investors, Accessibility, Privacy and Terms pages.
- Newsletter, preferences, social links and app-store coming-soon actions in the footer.

## UX, accessibility & responsive design
- Desktop navigation, mobile drawer and mobile bottom navigation.
- Toast system, loading states, empty states and route error boundary.
- Visible keyboard focus, reduced-motion handling and accessible labels for key icon controls.
- Responsive account, checkout, grocery, tracking, support and footer layouts.

## Developer quality
- Central constants, storage, coupon, status and API helpers.
- Auth and toast contexts plus reusable protected route/error boundary.
- Coupon and order-status unit tests.
- ESLint config and `npm run lint` script.
- `.env.example`, `.gitignore`, backend syntax checks and FoodRush package metadata.

## External-service boundaries
FoodRush runs without payment-provider credentials because checkout intentionally does not transfer real money. Email/SMS codes are generated by the bundled backend so the full local flow can be exercised; connecting an SMS/email provider would be required for real delivery to a device/inbox. Public OpenStreetMap data does not provide full commercial restaurant menus or verified consumer ratings, so FoodRush supplies its own menu/rating presentation where those fields are unavailable.
